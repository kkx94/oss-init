# v0.3.1 Application Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a safe, correctly packaged, cross-platform v0.3.1 that can be published to npm and used as credible evidence for the September 2026 Codex for Open Source application.

**Architecture:** Split project-name derivation and manifest validation into pure modules with explicit interfaces, then keep filesystem and child-process effects in the command layer. Generated workflows follow the same fail-closed release and stable-CI rules as the parent repository. Existing v0.2/v0.3 manifests remain readable through an explicit legacy migration.

**Tech Stack:** Node.js ESM, `node:test`, zero runtime dependencies, GitHub Actions, npm scoped public package.

## Global Constraints

- Preserve the zero-runtime-dependency policy.
- Support maintained Node releases: Node 22 and Node 24; test Node 26 as current without making it the minimum.
- Exercise Linux and Windows in CI; add macOS only for a demonstrated platform-specific need.
- Never put npm, GitHub, or other credentials in source, logs, prompts, or chat.
- Preserve user-edited scaffold files unless `--force` is explicit.
- Reject unsafe manifest input before render or target writes.
- Keep `@kkx94/oss-init` as the npm package and `oss-init` as the executable.
- Do not implement `--template`, Go templates, or unrelated refactors before the application.
- Preserve and incorporate the five existing working-tree changes after independently reviewing them.

---

## Planned File Structure

- Create `src/project-identity.js`: language-aware package, repository, JavaScript, and Python name derivation.
- Create `src/manifest.js`: manifest constants, legacy migration, schema validation, hash validation, and manifest construction.
- Create `scripts/verify-release.js`: compare the pushed tag with `package.json` and inspect package identity before publication.
- Modify `src/commands/init.js`: orchestrate identity resolution, safe process execution, and manifest construction.
- Modify `src/commands/update.js`: validate/migrate before render, enforce containment, guarantee cleanup, and write the current manifest schema.
- Modify `src/render.js`: enforce destination containment at the filesystem-write boundary.
- Modify templates under `src/templates/`: use correct repository identity, maintained runtimes, and fail-closed workflows.
- Modify `.github/workflows/ci.yml` and `.github/workflows/release.yml`: cross-platform CI, stable aggregate check, least privilege, and verified publication.
- Create `.github/dependabot.yml`: keep GitHub Actions references reviewed and current.
- Modify `test/*.test.js`: focused unit and end-to-end regression coverage.
- Modify `README.md`, `CHANGELOG.md`, `.gitignore`, and `package.json`: v0.3.1 release truth and cleanup.
- Ensure personal machine and tool configuration is absent from the public repository.

Write the manifest through a sibling temporary file and `renameSync` after all target operations succeed. Existing user-modified and retired-file behavior remains unchanged.
